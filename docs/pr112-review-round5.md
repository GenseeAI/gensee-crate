# PR 112 review follow-up (5126518126)

1. **ID-less approvals.** Exact attribution now accepts the alert's own PreToolUse entity in the same request, at or before the finding, even without a tool ID. The approval backend previously required a tool ID too, contrary to the review's claim that it already accepted these records. Recovery now supports the entity path end to end, matching provider, session, time, tool name, and working directory. Differing captures under that identity fail closed instead of selecting an arbitrary payload.
2. **Banner versus notification state.** Each new outage transition restores a dismissed banner even while native delivery is latched. Dismiss affects only the current incident; continued samples do not defeat that dismissal. Thirty seconds of stable health clears the stale banner and rearms notifications.
3. **Observation triage.** Pretool and observation findings share the resolved-path/structured-adjustment evidence adapter. Modern observation cleanup no longer depends on prose. Explicit non-routine adjustments remain visible, as do failed resolution and protected targets. Tests rename the production observation message and still verify quiet classification.
4. **Unknown configuration.** The configured mode starts unknown. Alarms stay silent until the host confirms a mode; the host records that result before unrelated policy reads can fail. Other refreshes cannot overwrite it with the model's unconfirmed default.
5. **Cache recency.** Retention is LRU rather than FIFO. Accessing an older warm context refreshes metadata, without reclassification. The most-recent warm context avoids the writer lock. Tests keep an active policy warm while registering ten cold contexts. Policy JSON formatting/key order no longer churns keys. The full semantic document stays in the key to avoid omitting a classifier dependency.
6. **Startup ownership.** The delegate subscribes to extension state and starts the sensor only after activation. It owns the single initial refresh; dashboard views no longer repeat sensor/policy startup. Dead menu-bar view implementations are removed. A policy-refresh guard prevents overlapping reads, and dashboard completion processing waits for a real snapshot rather than seeding empty startup data. After activation, sensor outages continue to be monitored even if extension status later changes.
7. **Contract guard.** The classifier is a named function. A pinned digest covers 576 default-policy evidence cases plus all four contract versions. Behavior changes covered by the corpus fail a test instructing the author to bump the relevant version and review the pin. CLI/store contracts are bumped to 2. This complements review; a finite corpus cannot prove all behavior is covered.
8. **One attribution implementation.** Request-detail and global dashboard queries share the SQL exact-event selector, also used by approval recovery. The separate Rust enrichment implementation is removed. Display fallbacks remain available but cannot advertise approvals.
9. **State/API cleanup.** Outage-window resets share a helper; expired wake grace is cleared. Installing dashboard SQL functions no longer requires a fake classifier key or registers a generation.
10. **Wake timing.** If the sensor dies during sleep and no poll succeeds afterward, stale time elapses inside the 30-second wake grace. The outage alarm therefore occurs around 40 active seconds after wake (30 grace + 10 outage grace), plus scheduling delay—not 55. A pre-sleep notification latch rearms after 30 seconds of wake grace plus 30 seconds of stable health. Successful post-wake polls move the subsequent stall deadline to 25 seconds after the last response. Drop counters survive grace and recovery.
